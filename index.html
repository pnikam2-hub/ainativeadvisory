The Three Agents

Plan · Monitor · Alert

Three specialised AI agents — each with a distinct job, sharing the same domain knowledge.

🧠

Plan Agent — The Architect

Takes a project brief + domain pack → generates 100+ tasks across 8 phases with milestones, dependencies, and discipline assignments. Catches scope gaps automatically: "You have tasks for gasifier procurement but nothing for biomass storage yard."

Uses an LLM — your choice of provider (OpenAI, Anthropic, OpenRouter). Falls back to template plans if no LLM key is configured.

👁️

Monitor Agent — The Inspector

Runs deterministic checks — no LLM required (fast, predictable, auditable). Reads monitoring rules from the domain pack, runs weekly or on-demand, flags drift from plan, delays, missing deliverables, and risk triggers before they escalate.

Example rule: "If HAZOP close-out < 80% and 4 weeks since completion → flag as critical"

🔔

Alert Agent — The Watchdog

Reviews anomalies detected by the Monitor Agent, escalates based on severity (info → warning → critical), cross-references against the risk register for recommended actions. Resolved alerts are logged for a complete audit trail.

Hybrid design: Plan + Alert use LLMs (creative work). Monitor is rule-based (zero LLM cost). Critical checks are always fast and predictable.

The Data Model

One Source of Truth — No Side Spreadsheets

Everything the agents act on is a record in the platform, keyed to the domain pack. Nothing important lives in a tracker someone keeps privately.

How a Project Is Modelled

  • Project — brief, scope, domain pack ID, status, dates, tags, budget, currency
  • Tasks — 8-phase WBS with discipline, dependencies, assignee, status, priority, estimated vs actual hours and cost
  • Risks — probability, impact rating, owner, mitigation, contingency, and the trigger conditions the Monitor Agent tests
  • Monitoring rules — threshold, severity, escalation path, and the risk each one maps back to
  • Alerts — rule hit, severity, source task or risk, recommended action, resolution state, timestamp
  • KPIs — defined by the pack and tracked against the project, so reporting is comparable project to project

Milestones Without a Second Object

Milestones are modelled as zero-hour tasks carrying the milestone priority — not as a separate entity living outside the plan.

  • The plan and the milestone list cannot drift apart — they are the same records
  • Dependencies attach normally, so milestones behave correctly in sequence logic
  • Zero estimated hours keeps them out of effort and cost roll-ups automatically
  • The same rule engine monitors them — no special-case code, no separate milestone report to keep in sync

Traceability to your systems of record

Every project, task and risk can carry its external ID from your ERP or scheduling tool (WBS element, MS Project UID, Jira key). That is what makes the integration layer, the sync log, and cost or schedule reconciliation possible — and auditable.

The Intelligence Layer

Domain Packs — Pre-Built Industry Knowledge

A domain pack is a folder of JSON and Markdown files. No database, no special tooling — edit in any text editor. Agents read the pack to know what to look for in your specific industry.

What's Inside a Pack

  • WBS template — 80–165 tasks per pack across 8 phases
  • Risk register — 40–88 risks with owner roles, early warning signals, mitigation, contingency
  • Monitoring rules — 25–40 rules with severity, thresholds, and escalation paths
  • KPI definitions — 25–40 KPIs tied to project outcomes
  • Procurement, permitting & commissioning checklists — 30+ items each
  • Agent context — domain knowledge that teaches the agents what matters

Two Deployment Models

Standalone or Intelligence Layer

Agentic PMO adapts to your project scale — no forced migration, no rip-and-replace.

Model A — Standalone

For small to medium projects

Agentic PMO is your primary project management tool. The Plan Agent generates the full WBS, the Kanban board tracks execution, and the Monitor Agent runs weekly checks. Works with any document repository — Google Drive, SharePoint, Dropbox, or a CDE like Autodesk Docs.

Best for: Plant expansions, retrofit projects, pilot plants, green fuel feasibility studies — 12 to 24 month projects.

Model B — Intelligence Layer

For large capital projects

Your organisation already runs Primavera P6 or MS Project. Agentic PMO sits alongside these as an intelligence layer — connected via a custom-built integration layer. No migration needed. No data duplication.

Agentic PMO handles: Domain WBS generation, risk flagging, monitoring rules, KPI tracking, scope gap detection, compliance checks, AI-driven risk escalation

Your tools remain: Primavera P6 / MS Project (schedule of record), CDE/DMS (document repository), ERP (budget of record)

Best for: Greenfield EPC plants, large infrastructure projects, multi-year capital programmes

Governance & Assurance

Autonomy With Receipts

A PMO that acts without a trail is a liability. Agentic PMO is built so that anything an agent flags, recommends, or changes can be reconstructed afterwards.

📜

Auditable by Design

The Monitor Agent is deterministic and rule-based: same inputs, same outputs. Any flag can be traced to the exact rule, threshold, and data point that produced it — which is what makes it usable as evidence in a client or regulator conversation.

🧑‍⚖️

Humans Keep the Pen

Agents recommend. No task is closed, no date is moved, no cost is committed, and no escalation reaches a client by an agent acting alone. Every alert carries a recommended action, waits for a human decision, and logs both.

🔒

Data Minimisation

What reaches an LLM is task titles, descriptions, and domain pack rules — no PII, no financial data, no documents. Documents never leave your CDE: the platform reads metadata and status, not drawings and specifications.

Why Custom-Built Is the Right Approach

  • Every enterprise runs Primavera differently — custom fields, unique workflows, specific permissions
  • Your sync cadence, conflict resolution rules, and data mappings are unique to your project
  • A custom connector takes 8–12 days to build and deploy — faster than adapting a generic one
  • Built with our AI coding tools — testable against your live environment from day one
  • No architectural changes needed to Agentic PMO — the sync engine is a standalone Python service running on cron

Security & Data Flow

  • No vendor cloud. Runs on your infrastructure — VPS, on-prem, or your cloud account
  • Documents never leave your CDE. Metadata only — no downloading drawings or specs
  • LLM data stays minimal. Task titles, descriptions, and domain pack rules only — no PII, no financial data
  • Integration layer runs inside your network. The sync engine connects from your infrastructure to your tools

Roadmap & Limits

What's Shipping Next, and What It Won't Do

We would rather you knew the edges of the platform before a pilot than after one.

On the Roadmap — In Build, Not Shipped

  • Monte Carlo risk engine — cost and schedule simulation over 10,000 iterations using PERT, Triangular, LogNormal, Uniform and discrete distributions, with correlated risks, S-curves, tornado sensitivity, P50/P80/P90 confidence levels, and baseline-vs-scenario comparison
  • Pluggable connector hub — declarative connectors (SAP S/4HANA, MS Project, Primavera) replacing bespoke sync scripts, each with its own sync log
  • Pack manifests — each pack declares which modules it needs (simulation, checklists, connectors), so the platform activates only what is relevant to that sector
  • Portfolio view — one dashboard across projects and pack types, not one project at a time
  • PostgreSQL, Redis and object storage — for multi-project, multi-team deployments with role-based access control

Honest Limits

  • It is not a schedule of record for large programmes. Keep Primavera P6 or MS Project and run Agentic PMO as the intelligence layer (Model B)
  • Pack quality bounds output quality. A thin domain pack produces a thin plan — the SME workshop is not optional
  • Four packs today. New packs take 2–3 days with one subject-matter expert; a pack marketplace is a roadmap item, not a claim
  • Integration is custom per client (8–12 days) — connectors are script-driven today, not yet self-service
  • Agents flag and recommend; humans decide. The platform makes no autonomous commitments on your behalf
  • Simulation and portfolio features are in build, not in production. We will tell you exactly which of the above is live on the day you ask
